# LUXEL — особистий кабінет клієнта

Веб-застосунок на Next.js у фірмовому стилі LUXEL: клієнти входять за логіном/паролем, бачать каталог товарів (фото, відео, опис, залишок), позначені акції, читають сповіщення й оформлюють замовлення з промокодами на знижку. Адміністратор керує товарами, залишками, клієнтами, акціями, сповіщеннями, промокодами, формує маршрути доставки та бачить карту покриття всіх точок клієнтів.

## Стек

- Next.js 16 (App Router) + TypeScript + Tailwind CSS
- Prisma ORM + SQLite (для прототипу; легко перемкнути на PostgreSQL для продакшена)
- NextAuth.js v5 (Credentials) — email/пароль, ролі ADMIN/CLIENT
- Leaflet + OpenStreetMap — вибір геомітки на карті (без платного API-ключа)
- Файли (фото/відео) зберігаються в `public/uploads`

## Демо-доступ

- Адмін: `admin@demo.local` / `password123`
- Клієнт: `client@demo.local` / `password123` (вже має 2 магазини з геомітками — Хрещатик і Оболонь)

## Каталог товарів

`npm run db:seed` завантажує **874 реальні товари** (з фото) з luxel.ua у 8 категоріях: LED Лампи, LED Освітлення, Електрофурнітура, Подовжувачі, Аксесуари, Фітоосвітлення, Генератори, WiFi Smart. Джерело даних — `prisma/luxel-catalog.json`, фото лежать у `public/catalog/`. Залишки після імпорту виставлені за замовчуванням (20 шт) — адміністратору потрібно один раз вручну оновити реальні залишки в `/admin/products` (там є швидке редагування прямо в таблиці).

## Запуск локально

```bash
npm install
npm run db:seed   # створює демо-користувачів, товари та магазини (якщо БД порожня)
npm run dev        # http://localhost:3000
```

Перша сторінка — `/login`. Без входу решта розділів недоступні (захист через proxy/middleware).

## Що реалізовано

**Клієнт**
- Каталог: фото, відео, опис, ціна, залишок, позначка «Акція» з текстом акції
- Кошик і оформлення замовлення з вибором магазину доставки (якщо у клієнта кілька точок) і полем промокоду (перевірка знижки ще до оформлення)
- Профіль (`/profile`): контактні дані компанії + список магазинів/точок доставки, кожен з адресою, контактною особою, телефоном і геоміткою на карті (можна додати скільки завгодно магазинів)
- Історія замовлень зі статусами та застосованою знижкою
- Банер зі сповіщеннями від адміністрації

**Адмін**
- Товари: CRUD, завантаження фото/відео, швидке редагування залишку прямо в таблиці (для ранкового оновлення), позначення акцій
- Клієнти (`/admin/clients`): зручна форма створення клієнта (ім'я, email, пароль з кнопкою «Згенерувати», компанія) — без ручних скриптів
- **Промокоди** (`/admin/promocodes`): створення кодів на знижку у % або фіксовану суму, ліміт використань (1 — для розіграшу з одним переможцем, більше — для акцій, порожньо — без обмежень), термін дії, автогенерація коду, вмикання/вимикання
- **Карта покриття** (`/admin/coverage`): усі точки клієнтів на одній карті (OpenStreetMap) + таблиця з адресами, контактами та кількістю замовлень, кнопка «Завантажити CSV» для вивантаження в Excel
- Сповіщення: розсилка повідомлень усім клієнтам
- Усі замовлення зі зміною статусу
- **Маршрути доставки** (`/admin/routes`):
  - створення маршруту на дату з вибраних замовлень (групуються по магазинах клієнтів)
  - ручне сортування зупинок (кнопки вгору/вниз)
  - **друк погрузочного листа** — кнопка «Друк», окремий формат для паперу з переліком товарів по кожній зупинці
  - **цифровий маршрут для Google Maps** — кнопка відкриває маршрут з усіма точками у Google Maps (безкоштовно, без API-ключа)
  - орієнтовна відстань між зупинками та загальна (по прямій лінії — детальніше нижче)
  - позначення всього маршруту як доставленого (статус замовлень → «Відправлено»)

## Про розрахунок відстаней і карту

Геомітки клієнти обирають самі, клацнувши на карті (OpenStreetMap, безкоштовно). Посилання на маршрут відкривається в Google Maps без API-ключа. Відстань між зупинками рахується по прямій лінії (формула гаверсинуса) — це орієнтовний показник, реальна відстань по дорогах зазвичай на 15-30% більша. Якщо потрібна точна відстань і побудова оптимального маршруту по дорогах — знадобиться платний Google Directions API (можна підключити пізніше, замінивши функції в `src/lib/geo.ts`).

## Що варто доопрацювати перед бойовим запуском

1. **База даних**: перейти з SQLite на PostgreSQL. Змінюється лише `DATABASE_URL` і `provider` в `prisma/schema.prisma`.
2. **Сховище файлів**: фото/відео зараз лежать на диску сервера — при переїзді на serverless-хостинг (Vercel) варто підключити S3-сумісне сховище (Cloudflare R2, Yandex Object Storage тощо).
3. **NEXTAUTH_SECRET**: згенерувати випадковий секрет для продакшена (`openssl rand -base64 32`), не зберігати в репозиторії.
4. **Хостинг**: підійде звичайний VPS (Hetzner, Timeweb, Selectel) з Node.js + Nginx, або PaaS (Vercel/Render).

## Структура проєкту

```
src/
  app/
    login/                  — сторінка входу
    page.tsx                 — каталог + кошик (клієнт)
    profile/                 — профіль клієнта: контакти + магазини з геоміткою
    orders/                   — історія замовлень
    admin/
      products/               — товари та залишки
      clients/                — створення та список клієнтів
      routes/                 — список, створення та деталі маршрутів доставки
      coverage/                — карта покриття всіх точок + CSV-експорт
      promocodes/              — промокоди на знижку
      announcements/          — сповіщення
    api/                       — REST API (products, orders, shops, routes, promo, admin/clients, admin/shops, admin/promocodes, auth, upload)
  components/
    Navbar.tsx, MapPicker.tsx, CoverageMap.tsx, SessionProviderWrapper.tsx
  lib/
    prisma.ts, auth.ts, geo.ts (відстані та посилання на Google Maps), promo.ts (валідація та розрахунок знижки)
prisma/
  schema.prisma               — моделі даних (User, Shop, Product, Order, PromoCode, Route, RouteStop...)
  seed.ts                      — демо-дані
public/
  brand/logo.png               — фірмовий логотип LUXEL
```
